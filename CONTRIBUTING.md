# Contributing

This repository is one OpenCode plugin on [plugin-contract v0](https://github.com/we-the-rebel-alliance/plugin-contract).
The [plugin standard](https://github.com/we-the-rebel-alliance/plugin-contract/blob/master/docs/plugin-standard.md) and
the [contract](https://github.com/we-the-rebel-alliance/plugin-contract/blob/master/docs/contract.md) decide; `AGENTS.md`
is the short version for this repository.

## Set up

```sh
npm ci
npm run check
```

`npm ci` installs dev tooling only: the plugin has no runtime dependencies, and `dist/index.js` is self-contained except
for `@opencode/*`.

## Checks

`npm run check` runs, in order:

1. `biome check .` (lint and format);
2. `tsc --noEmit`;
3. the esbuild bundle;
4. `vitest run` (unit, conformance and the real 2.4.1 host);
5. `plugin-kit check` (T0, the declaration, the recordings, T1 and the unsupported host);
6. `npm pack` and an import of the packed entry.

A full check loads the real host; run one at a time on a shared machine.

## The manifest first

Change `capabilities` in `package.json` before the code: a method, source or action, with its class, operations,
accounts and cost. Then the handler in `src/handlers/`, the provider call in `src/provider/`, and the tests. The
register refuses a handler the manifest does not declare, and a declared method without one.

## Docs and skills

Generated sections sit between `<!-- generated:<section> -->` and `<!-- /generated:<section> -->`. Edit the manifest,
then run:

```sh
npx plugin-kit docs
```

CI fails when a section drifts. A skill names only declared tools: `tools.ashby.<method>` for the plugin's own methods,
and `ashby_<tool>` (or `<server>_<tool>` for an alias) for a pass-through tool. Never hard-code an account.

## Fixtures

`fixtures/conformance.json` is generated by `test/conformance/fixture.test.ts` from a fake Ashby MCP transport, for two
synthetic aliases. Regenerate it after changing an answer:

```sh
UPDATE_FIXTURES=1 npx vitest run test/conformance/fixture.test.ts
```

Every person, job, id and link in it is invented. For a real-account recording, use `npx plugin-kit record
--account <alias>`; it redacts secrets and personal data before writing.

## Commits and pull requests

Conventional commits (`feat:`, `fix:`, `docs:`, `test:`, `chore:`). One pull request per change, with the sections
**What changed**, **Why**, **Spec section**, **Checks**, **Closes #<issue>** and **Open questions**. The required check is
`ci`. Never push to `master`.

## Release

The maintainer cuts a release on `master`:

```sh
npx plugin-kit release 0.0.0
```

The command requires `package.json` and `CHANGELOG.md` to be ready, runs the checks, and creates the annotated tag. CI's
`release.yml` then publishes the GitHub release with the tarball, `SHA256SUMS` and the conformance report. There is no
npm publish.
